# Flagship feature-to-hardware matrix

Revision F0-A1 · 2 October 2026 · Hardware capability audit, not an implementation or commissioning certificate

Authority: the six F0 flagship documents, especially [BOM](02_COMPONENTS_AND_BUDGET.md), [interfaces](04_INTERFACES_POWER_MECHANICS.md) and [validation gates](05_VALIDATION_SCALABILITY_AND_GATES.md). All F01–F27 selections remain unchanged. See [final audit](FINAL_HARDWARE_GAP_AUDIT.md) for the decisions and sources.

**Interpretation:** YES means the selected hardware supplies a plausible acquisition/compute path for the existing bounded research demonstration after integration and calibration. It does not mean that path is already implemented, tested, accurate or safe for industrial operation. CONDITIONAL explicitly retains a measurement limitation. No row authorizes an invented value. All G01–G14 release gates remain open until separately evidenced.

Domain: manual braked cart, no rider, segregated level dry course, initially stationary then at most 1 m/s after review, forward measured 1–15 m test stations with only validated subsets used, outdoor open-sky GNSS and two physical participants. Indoors use labelled replay. Node B is a location-only cooperative participant, not a second full sensor vehicle.

## Result

All ten feature groups have an existing hardware path for the bounded demonstrator. The conditional cases are explicit limits of the approved domain, not permissions to invent missing measurements. No new hardware is required. This conclusion does not establish software completion, simultaneous sensor performance, commissioning, industrial feasibility at scale or fabrication readiness.
