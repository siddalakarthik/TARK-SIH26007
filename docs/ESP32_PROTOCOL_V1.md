# TARK Pi ↔ ESP32 Protocol V1

This is the sole binary protocol specification for the local Pi-to-ESP32
control boundary. Its executable references are
`backend/app/communication/esp32/protocol.py`,
`firmware/esp32/main/protocol/`, and `protocol_vectors.json`.

## Safety meaning

`ACK` means only that the ESP32 **software supervisor** accepted a command.
It does not establish a physical motor output, MDD10A energization, wheel
response, vehicle movement, braking, contactor state, or E-stop isolation.
In Phase 1, applied output is permanently zero and the output state is
`DISABLED_PHASE_1`.

## Wire frame

Each frame is delimited by byte `00`:

```
00 | COBS(encoded_body_and_crc) | 00
```

After COBS decoding, the byte sequence is:

| Offset | Size | Field | Encoding |
|---:|---:|---|---|
| 0 | 2 | magic | `0x544B`, big-endian |
| 2 | 1 | version | `1` |
| 3 | 1 | message type | listed below |
| 4 | 4 | payload length | unsigned big-endian, maximum 512 |
| 8 | 8 | sequence slot | unsigned big-endian; V1 semantic range 0…`0xFFFFFFFF` |
| 16 | 8 | timestamp ns | unsigned big-endian monotonic timestamp |
| 24 | N | payload | canonical CBOR definite-length map |
| 24+N | 4 | CRC-32C | unsigned big-endian CRC of all preceding decoded bytes |

The maximum fully framed object is 640 bytes. CRC-32C uses the reflected
Castagnoli polynomial `0x82F63B78`, initial value `0xFFFFFFFF`, final XOR
`0xFFFFFFFF`. COBS is standard byte stuffing with the outer delimiters not
part of the COBS data.

## Types and payloads

| Value | Name | Required payload contract |
|---:|---|---|
| 1 | COMMAND | `protocol_version`, `sequence`, `timestamp_ns`, `valid_until_ns`, `state`, `permitted_speed_mps`, `left_command`, `right_command`, `heartbeat`, `reason_code`, `configuration_hash` |
| 2 | ACK | `accepted: true`, `reason`, `output_state`, `applied_left`, `applied_right`, `source_mode` |
| 3 | NACK | `accepted: false`, `reason`, `output_state`, `applied_left`, `applied_right`, `source_mode` |
| 4 | HEARTBEAT | `protocol_version`, `configuration_hash` |
| 5 | STATUS | telemetry-only map; current vector has `reason`, `output_state` |

COMMAND requires a matching header/payload sequence and timestamp, V1,
matching configuration hash, a future `valid_until_ns`, approved state
(`NORMAL`, `WARN`, `RESTRICT`, `UNKNOWN`, or `STOP`), finite numbers,
non-negative permitted speed, and `abs(left_command/right_command) <= 1`.
Malformed or inconsistent data is rejected; it is never repaired.

Canonical NACK/diagnostic reasons include `DUPLICATE_SEQUENCE`,
`OLD_SEQUENCE`, `OUT_OF_ORDER_SEQUENCE`, `COMMAND_EXPIRED`,
`HEARTBEAT_TIMEOUT`, `CONFIGURATION_MISMATCH`, `INVALID_PAYLOAD`,
`INVALID_VERSION`, `INVALID_CRC`, `INVALID_LENGTH`, `NOT_ENABLED`, and
`INTERNAL_FAULT`.

Unknown protocol versions and unknown message types are rejected without
best-effort decoding. A sequence response correlates only with the identical
pending Pi command sequence.

## Golden vectors

`protocol_vectors.json` is the canonical source. It fixes logical payload,
canonical CBOR bytes, expected CRC-32C and full COBS frame for COMMAND, ACK,
NACK, STATUS and a boundary HEARTBEAT. The checked C header is generated by
`scripts/generate_protocol_vectors.py`; Python tests consume the JSON directly
and firmware host tests consume the generated header.

The vectors prove byte-level codec/envelope compatibility only. They do not
prove a physical serial device, ESP32 flash, physical watchdog, MDD10A,
encoder, contactor, E-stop, or traction behaviour.

## Firmware service boundary

`firmware/esp32/main/protocol/service.*` is the board-independent RX/TX
boundary. It accepts arbitrary byte chunks into a fixed 640-byte encoded-frame
buffer, handles partial/multiple/delimiter-recovered frames, validates the
envelope and canonical CBOR, invokes the command supervisor, then emits one
whole response frame through an injected TX callback. There is no dynamic
allocation, GPIO access, PWM access, or physical USB driver in this layer.
Response construction is centralized in `response.*`; ACK/NACK applied values
are hard-coded zero and output state is `DISABLED_PHASE_1`.
